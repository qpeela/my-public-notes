Одна из важных штук, но и в принципе все сейчас с этого начинают, а не с теории, которую я разобрал в цикле заметок по Unit тестированию - это Фреймворк для тестирования. Фреймворк для тестирования помогает подготовить данные для выполнения тестируемого кода(обычно это мы делаем в блоке фrrange):
- Параллельно запускать тесты
- Изоляция тесто - очищение
- Фильтрация - запуск только определенного подмножества тестов
- Посмотреть coverage(покрытие) тестов, какой код был запущен при проверке тестов
- Маги времени - помощь в тестирование с задержкой по времени (setTimeout, setInterval)

Как начать писать тесты
- Лучше начать с написания посредственных тестов, которые несут бизнес ценность прям сейчас. Например есть баг → пишем тест, который вопроизводит баг, то есть тест “красный” → фиксим баг → тест проходит “зеленый”. И используй такой подход в работе в течение 2-3 месяцев, пока находим ошибки в коде. Параллельно мы привыкаем писать тесты и уже сможем начать писать тесты на разрабатываемые фичи. 
- После того как хорошо разбираемся в написание тестов можем писать тесты при рефакторинге кода. Вначале добавляем тесты, потом рефакторим → Проверяем наши тесты
